# Overview
This is our SRS document. This document defines all the functional and non-functional requirements for our system. we will be updating this as we continue the project.  This is just the source of truth document for what we plan to include in our system. 
# Functional Requirements
1. Account Feature
   - The system shall allow users to create an account.
   - The system shall allow account to email user with a reminder.
   - The system shall allow users to view their upcoming reservations.
2. Reservation System
   - The system shall allow the user to pick a time slot for the reservation
   - The system shall allow a user to look at future dates to find available rooms.
   - The system shall generate a unique check-in code for each reservation.
   - The system shall allow a user to cancel an upcoming study room reservation. 
   - The system shall prevent a user from reserving a study room that is already booked for the selected time.

# Non-Functional Requirements
1. Account Feature
   - The system shall only allow one user per account.
2. Reservation System
   - The system shall allow a user to reserve multiple rooms across different dates.
   - The system shall update room availability within five seconds of a reservation change.
3. Useability
   - The system shall store user data safely.
   - The system shall allow pages to load quickly between tabs.
